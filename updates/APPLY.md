# 적용·검증·복구

## Codex에 맡기는 방법

1. 필요한 기능 ZIP을 내려받아 프로젝트 외부에 압축을 풉니다.
2. 본인 프로젝트를 Codex에서 엽니다.
3. ZIP의 `CODEX.md` 요청문에서 경로를 채워 붙여 넣습니다.
4. 적용 결과와 테스트를 확인한 뒤, 원하는 경우 본인의 Cloudflare에 배포를 요청합니다.

트윗 선택 기능은 표시 이름 기능이 먼저 필요합니다. 다른 기능들은 각각 선택할 수 있습니다. 운영 배포는 설명서와 요청문에서 별도 단계로 구분했습니다.

## 직접 적용하는 방법

모듈별 README의 순서를 따릅니다. 적용 전에는 개인 수정과 대상 파일을 복구 가능하게 보관하세요. 먼저 `check.mjs`로 패치 무결성·선행 기능·적용 가능 여부를 확인합니다.

검사 통과 후 `git apply --check`와 `git apply`로 해당 패치만 반영합니다. 저장소 전체나 `public` 폴더 전체를 교체하지 마세요. 패치에는 필요한 실행 코드와 회귀 테스트만 들어 있습니다.

각 README에 적힌 테스트를 실행하고 로컬 화면에서 사용 흐름을 확인합니다. 명령 성공과 실제 화면 확인은 별개입니다. 다른 기능을 함께 사용한다면 관련 테스트도 실행하세요.

새 DB 마이그레이션은 없습니다. 원본의 `wrangler.jsonc`, `public/config.js`, 사진 파일 또는 `.dev.vars`를 복사할 이유가 없습니다.

## 적용이 안 될 때

- 이미 적용됨: 다시 적용하지 않습니다.
- 선행 기능 없음: 해당 ZIP을 먼저 적용합니다.
- 파일 충돌/다른 버전: 현재 코드를 보존하고 Codex 요청문으로 필요한 부분만 통합합니다.
- 일부 기능이 이미 있음: 존재 여부와 동작을 비교하고 중복 코드가 생기지 않게 합니다.

충돌을 없애려고 `git reset --hard`, `--reject` 또는 전체 파일 덮어쓰기를 사용하지 마세요.

## 복구

후속 의존 기능부터 역순으로 되돌립니다. 예를 들어 트윗 선택 기능을 되돌린 다음 표시 이름 기능을 되돌립니다. `git apply --reverse --check`에 통과할 때만 역방향 패치를 적용합니다. 후속 개인 수정과 충돌하면 백업과 비교해 해당 변경만 복구하세요.

코드 복구와 원격 데이터 복구는 다릅니다. 이 절차는 사진이나 DB를 지우거나 되돌리지 않습니다. 운영 사이트의 코드를 되돌릴 때는 본인 설정으로 재배포하고 브라우저에서도 확인합니다.
